The fluid grid is a CPU allocation control. A reproduced destroyed-texture submission error occurred when an old-grid initialization was encoded before a grid change allocated new textures. Allocation now happens before encoding; regression tests change grids while paused and with queued updates on all three material models.

Hardware tests also exposed pigment loss hidden by the software adapter: repeated half-float pigment/paper writes lost 1.11% after 32 stationary updates and 2.24% after 64. Ink now stores both pigment and paper in `rgba32float`, retaining half-float velocity. The same Chrome/WebKit fixture has approximately 2.2×10⁻⁹ relative error after 64 updates with unchanged test tolerances. This costs 32 additional logical bytes per cell compared with the original ink allocation. Advective transport still has the documented semi-Lagrangian losses.

## Scope and limits

This milestone uses small fixed-grid software fixtures to catch numerical and lifecycle regressions; those fixtures do not establish high-resolution accuracy or speed. The 1024² hardware gate is separate. Finite Jacobi pressure iterations leave a measurable divergence residual, semi-Lagrangian transport loses detail and material, and half-float state rounds. The notes describe each algorithm's bounds and approximations.

Adaptive quality changes work per fixed tick. Fluid pressure convergence decreases as iterations scale down; cellular effects that perform several iterations per tick can evolve more slowly. Presentation resolution and simulation grids are independent. The controller observes queue-completion wall load after submission, warms up for thirty samples, requires twelve slow samples to degrade, and 120 fast samples to recover. It is an optional first version, with no GPU timestamp attribution or automatic simulation-grid changes. Turning it off restores the selected resolution ceiling and full work count.

Texture captures are explicit snapshots, avoiding continuous readback overhead during normal rendering. Passes list composed programs, named intermediate textures and buffer summaries; channel/range remapping and false colour happen after raw format-aware readback. Initial-state parameters take effect on reset. Time-scale controls change how many fixed 1/60 s steps run; single-step always advances one tick.

`fluid-obstacles`, DOM attachment, gallery/Compare/Grid/In-page stages, live shader editing, timestamp profiling, input textures and recordings remain in their later milestones. Native Safari/Firefox catalogue passes and other device classes remain M8 work.
