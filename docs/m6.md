# M6 — Geometry and baseline capability coverage

Implemented and locally validated 2026-10-07. All four Family G core effects are available in Full, Compare, Grid and DOM attachment modes through the existing catalogue. The catalogue now contains all 47 core effects plus Family A's three stretches. The [T5/HDR ADR](adr/018-minimal-geometry-and-hdr.md) fixes conventions, resource ownership and presentation behavior.

## Implementation

- `instances`: a seeded noise-displaced indexed cube field, direct/bundled instancing, single/4x MSAA, strict-less depth and visible/hidden occlusion probes. Default actual count is 4096; presets and controls reach 65,536. Queries are u64 buffer taps and exercise the real mesh draw, including bundle execution.
- `terrain`: an indexed 128²-cell xz grid, a seeded r32float height map, in-place per-texel smoothstep remap, vertex sampling/displacement, reconstructed normals, fog and an orbiting camera. Height generation is invalidated by seed, frequency, amplitude, sculpt and geometry changes. Without the WGSL read/write language feature, a fused write-only pass produces the same height field.
- `material-ball`: a unit sphere with metallic/roughness GGX, Schlick Fresnel, Smith visibility, a split-sum DFG approximation, procedural HDR cube lighting, seven specular roughness mips and separate cosine irradiance. Compute writes actual six-layer storage arrays; rendering samples actual cube views. All 54 source/specular/irradiance planes are inspectable.
- `glass`: full-size background capture, sphere refraction/dispersion and Fresnel/absorption, resolved transparent mesh layer and final composite. IOR 1 with zero dispersion/absorption reproduces the background inside covered pixels. Refraction uses a screen-space travel approximation.
- Core exports minimal column-major camera/matrix helpers, outward indexed cube/sphere/plane meshes, mesh upload, depth/MSAA targets, async mesh pipelines, deterministic cube direction and environment convolution. No scene graph or model loader was added.
- `createHDRCanvas` presents borrowed linear effect output on a separate opaque rgba16float canvas over black. It performs gamut conversion and the colour-space transfer function without clipping HDR values, verifies extended tone mapping, and releases resources on unsupported configurations. Dimensions, scheduling and device-loss rebuilding are caller responsibilities.

All four definitions have generated controls, two presets, source inspection/editing, quality ranges, a settled reduced-motion pose, fallback styles, individual public exports and completed research notes. Size-dependent targets and changed meshes are disposed; shader leases are released when detached.

## Baseline capability audit

This maps section 6.11 to concrete implemented paths. Optional GPU feature experiments, compatibility-limit testing and worker rendering remain M8. Read/write storage textures are a WGSL language capability rather than a requested `GPUFeatureName`; the effects detect it and preserve output through a fallback. HDR presentation is additionally browser/display gated.

Successful HDR configure/readback does not establish physical display luminance, gamut accuracy or translucent HDR page compositing. The HDR presenter uses opaque output; physical display checks remain M8. `slit-scan` and `culling` remain stretch effects because core paths now cover arrays and occlusion queries.

## Validation

Commands:

```sh
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
pnpm test:browser
pnpm exec playwright test tests/browser/m6-*.spec.ts --config playwright.hardware.config.ts
HOLOGPU_URL=http://127.0.0.1:5176 pnpm benchmark:m6 chrome

```

The unit suite passes 71 tests, including projection near/far mapping, view/matrix composition, valid mesh indices/outward winding/unit normals, invalid camera/mesh inputs and cube-face axes/seams. Catalogue discovery retains the 19-line T1 example.

M6 passes 26 software browser cases at DPR 1/2 and 39 hardware cases across Chrome, headed Playwright Firefox and Playwright WebKit. The cases cover deterministic replay and 24 preset/default snapshots; every enum; actual allocation changes; finite intermediate readback; paused/reduced-motion output; zero owned memory and zero cached shader references after destruction; direct/bundle equality; depth occlusion; cube radiance against CPU values; specular mip coverage; glass identity/dispersion; terrain remap/scaling/seed invalidation; real HDR rendering/numeric encoding where supported; and exact paused-pixel recovery after actual device loss for every new effect.

An initial hardware run had one Firefox `material-ball` page/context closure during repeated texture readback. Its complete nine-case Firefox rerun passed; all twelve additional hardware device-loss cases also passed; the other engines passed all nine cases, and the final HDR numeric check passed in all three engines (Firefox verifies the unsupported path). This transient browser closure is retained as a compatibility observation rather than hidden behind automatic retries. The initial development server also cached unresolved imports while new directories were populated; restarting cleared that development-only failure.

The full 448-case software regression run finished with 445 passes, two Firefox-only skips and one raymarch screenshot interruption: catalogue regeneration hot-reloaded the page between sizing and capture. With generated files frozen, that unchanged DPR-2 raymarch case passed its standalone rerun. Combined with the eight additional M6 device-loss cases, all 454 applicable software cases have passing final results; two Firefox-only cases are intentionally skipped in software configurations. No existing screenshot baseline was changed. Formatting, type checking and the production build pass.

## Measurements

[Chrome records](benchmarks/m6-chrome.json) and [WebKit records](benchmarks/m6-webkit.json) contain 24 benchmark rows: three runs for every new effect in each engine. Production preview, Apple M1 Max, macOS 26.6.2, DPR 1, physical 512² output, seed 7, current typed defaults, 4x MSAA, fixed quality, 30 warm-up updates and 120 measured fixed 1/60 s updates per run. Median observed cadence is 16.7 ms in Chrome and 17 ms in WebKit for every row. CPU encoding, encoding-through-queue-completion latency, per-pass GPU timestamps and rAF cadence measure different boundaries. Machine load is uncontrolled and other validation work may run concurrently. Quantized/overlapping GPU intervals are diagnostic; their sum is not whole-frame elapsed time. These are measurements rather than a refresh-rate gate: M6's exit is capability coverage. Logical texture allocation ranges from 14 MiB for instances to 18 MiB for glass at this workload, excluding driver pipeline/query storage and swap-chain memory.

## Limits and remaining work

Environment lighting is a 64-sample procedural fixture and DFG approximation; face-local source mips are not a seam-aware asset pipeline. Glass cannot recover off-screen scene data or actual two-surface thickness. Resolution quality reduces fragment work but does not reduce mesh count. Native Safari appearance, touch cameras, physical weaker devices and measured HDR-panel appearance remain M8 validation; optional-feature stretches retain their original scope.
