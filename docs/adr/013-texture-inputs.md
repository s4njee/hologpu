# ADR 013: owned linear texture inputs

Status: accepted, M4.

Backlog v2 section 3.4 adds scalar `mask` descriptors for image alpha, canvas data and SVG path strings. Coverage is uploaded to a single-channel linear `r8unorm` texture with one mip; it bypasses the colour normalizer and mip generator. Alpha is the default coverage, red preserves already-linear grayscale bytes for authored depth maps, and luminance decodes sRGB then applies Rec.709 weights and alpha. Static images and paths retain owned bitmap snapshots across restoration; mutable canvases are re-extracted during rendering and stay caller-owned. Scalar masks expose their real format and allocation size through inspection taps and memory reports.

`InputManager` adapts image, canvas, video, text, audio, CPU RGBA LUT data and other-effect texture descriptors to owned `rgba16float` textures. Each input has a complete area-weighted mip chain from the M3 mip generator. Construction allocates nothing; the first `set` compiles normalizers, and `prepare(frame, encoder)` records normalization before the effect's passes. Missing video frames or missing provider textures expose no input until data become available, allowing the effect's documented fallback.

Images are copied to an owned `ImageBitmap` before `set` resolves. Closing the caller's bitmap immediately is safe. Text rasterizes into an owned transparent white canvas. Static image/text inputs upload once; canvas and audio update at every preparation. Analyser inputs invalidate through an owned animation callback, so their signal can update while the effect transport is paused. On Chromium hardware, a video supplies a fresh `GPUExternalTexture` through `GPUDevice.importExternalTexture` for each new decoded frame, sampled at texel centers. Repeated renders of the same decoded frame reuse its owned normalized texture and mips. Current WebKit and Firefox use an owned canvas snapshot and `copyExternalImageToTexture`. WebKit evidence: its direct YUV external texture conversion disagreed with same-frame interior uniform patches (red 0.121887 linear versus Canvas2D reference 0.0003035), and snapshotting the video into a `VideoFrame` gave the same discrepancy. Firefox also disagreed after three identical paused Canvas captures and a fresh GPU upload: a uniform blue patch read 1.001953 linear through the external path versus Canvas encoded 243/255 (0.896269 linear), with the reference byte-identical across normalization. These values do not fit missing or doubled sRGB decode. The canvas upload preserves the original numerical tolerance and avoids CPU pixel readback. Its video-frame callback invalidates a paused field when new decoded content arrives. A parallel native `timeupdate` listener supplies a bounded backup when a hidden/non-presenting video stops delivering frame callbacks: only changed media time with decoded data invalidates, after 100 ms of callback silence and at most once per 100 ms. Explicit paused seeks bypass that freshness window. Neither path polls every animation frame or creates a second callback chain; disposal removes both event listeners and cancels the sole pending frame callback. On a fallback/software GPU adapter, browser media interop can fail before creating a valid external source texture (observed on SwiftShader). That adapter uses canvas readback and `writeTexture`; hardware adapters use the actual external APIs. `mediaPath` exposes `external`, `canvas-copy` or `software-copy`; benchmarks must preserve this distinction. The external texture is imported, bound and submitted in the same JavaScript task. It is never cached across tasks.

External image upload explicitly requests sRGB, straight alpha. A compute pass decodes the sRGB transfer function first and multiplies linear RGB by alpha afterward. This avoids filtering in encoded color and avoids multiplying the nonlinear transfer function's argument by alpha. External video reads return encoded sRGB values from the requested external color space; the same decode applies. Mips average linear premultiplied samples, so transparent edges do not acquire colored fringes. Text masks become premultiplied white. Already-linear premultiplied effect output is normalized without another sRGB decode; descriptors can explicitly declare straight alpha or sRGB sources. Intermediate HDR values retain their linear range.

An effect that declares `fieldInputSampling: 'base'` may borrow a ready, same-device `EffectField` output directly. This narrow path is for filters such as panel refraction that only sample the base level: it allocates no normalized copy or mip chain. Runtime dependency ordering and source output revisions keep consumers current across render, resize and restoration. Media, raw texture descriptors and all other effect definitions retain the owned normalization path above. Surface outputs support `COPY_SRC`, so public borrowed inspection taps can be read without a separate ownership transfer.

Audio inputs accept an `AnalyserNode`, or deterministic `Float32Array` FFT/waveform data. The texture is two rows: row zero contains linear FFT amplitude (`10 ** (dB / 20)` for analyser output), and row one contains signed waveform samples. Texture width is the full analyser `fftSize`, retaining every waveform sample; the FFT row is zero-padded after `frequencyBinCount`. Array fixtures use the longer input array as the width. Red stores the signal, alpha is one, and other channels are zero. This is data, so the normalizer does not apply sRGB conversion. Fixtures avoid requiring an actual microphone in tests.

Texture providers can return the latest tap after another field resizes. When a provider declares its session, the manager verifies GPU-device identity. A provider that becomes unavailable exposes no input or inspection tap, even if an older normalized copy is still allocated. Borrowed textures, DOM canvases, DOM videos, audio contexts, analyser connections and media-stream tracks remain owned by their callers. Replacement/deletion and disposal release the manager's textures, uniforms, bitmap snapshots, callbacks and shader leases. Pipeline builds hold local leases until their manager epoch and device generation are verified. Restoring or disposing invalidates every pending input name, including names without an allocated entry; stale asynchronous builds release their leases and cannot publish allocations. `restore()` reconstructs GPU resources from retained source descriptors after device recovery while caller media continue running. An application must submit any caller-owned encoder before replacing an input whose old textures it references.

The playground fixtures are original local assets: an SVG mountain illustration, a three-second 1920×1080 60fps FFmpeg test pattern in VP8 WebM and H.264 MP4, and a one-second 440Hz PCM WAV. Tests decode these assets rather than substituting a static canvas for video. Numerical tests compare actual GPU image/video pixels, linear alpha and mips against CPU references, and exercise caller bitmap closure, live canvas resize, replacement, audio uploads, borrowed-texture lifetime and manager resource rebuilding, and disposal/restoration while asynchronous pipeline compilation is deliberately delayed. GPU image/mip comparisons use the original 0.002 absolute tolerance; same-frame video interior patches use 0.03 to include decoder color quantization. No tolerance was widened for WebKit.

These interfaces convert semantic external colors to raw numeric GPU data; the core explicitly chooses the numeric representation used by effects.
