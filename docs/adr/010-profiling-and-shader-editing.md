# ADR 010 — Timestamp profiling and transactional shader edits

Status: implemented for M3.

The shared device requests `timestamp-query` only when the adapter advertises it. Profiling remains opt-in; unsupported devices keep CPU, frame-interval and queue-completion measurements. Compute and render helpers place beginning/end timestamp writes at pass boundaries. Results are unsigned 64-bit nanoseconds, converted to milliseconds after asynchronous readback. Repeated pass labels aggregate their durations and invocation counts. The displayed GPU total is the sum of measured pass intervals, not whole-frame or queue latency. Browser implementations may quantize these values, and comparisons between adapters require care. See [the pass timestamp API](https://developer.mozilla.org/en-US/docs/Web/API/GPUCommandEncoder/beginComputePass) and [WebGPU timing limitations](https://webgpufundamentals.org/webgpu/lessons/webgpu-timing.html).

A profiler owns at most three query/resolve/readback sets, each supporting 512 passes. Busy sets cannot be reused until mapping completes. Frames are skipped rather than blocking animation when all sets are busy; capacity overflow marks an incomplete capture. Submission resolves queries in the same encoder before finishing, then begins mapping after queue submission. Device loss/disposal destroys all allocations and suppresses delayed notifications. Histories retain at most 240 frames; logical buffer bytes exclude implementation-defined query storage and driver residency.

The local captures show some nearly identical intervals for adjacent render passes and summed intervals exceeding queue-completion wall latency. This establishes that the sum cannot serve as whole-frame execution time on this setup. Overlap and backend quantization are possible explanations; these measurements do not establish the cause. Raw per-pass diagnostics and the independently measured wall/cadence columns are retained without rescaling or clamping one to match another.

The Profiler drawer reports CPU encoding, a frame-interval histogram, current work/resolution quality, logical resources and per-pass GPU timings. Its fixed-scenario benchmark pauses playback, temporarily enables motion, fixes quality and time scale, sets a 512² CSS stage, resets seed 7, and advances one fixed tick per rAF. Thirty warm-up updates precede 120 measured updates; custom warm-up and sample counts are each bounded to 600. CPU encode, submit-to-completion wall latency, serialized rAF cadence and optional timestamp sums remain separate columns. Current parameters are recorded exactly; the original motion override and playback intent are restored afterward. Changes to transport, quality, instance, parameters, inputs or pointer state cancel the run before it can append mixed measurements. Exports append complete rows to a JSON results document. Hardware scripts use the same runner with DPR 1 and additionally inspect actual storage counts for the million-particle exit.

Shader edits rebuild an effect instance beside the running one. A per-build bound session proxy substitutes edited composed sources, leaving other fields and their shared cached pipelines unchanged. Shader modules and pipelines compile inside serialized validation scopes; syntax warnings/errors retain `getCompilationInfo` locations, and layout validation errors remain local to the attempted build. A failed or superseded candidate releases its allocations and leaves the previous instance active. A successful candidate replays retained local inputs, swaps atomically and resets simulation/history with the same seed. Image inputs retain a detached raster snapshot so closing the caller's decoded bitmap cannot break replay. State migration across arbitrary WGSL edits is deliberately unsupported. Source overrides are local to the field/session and export as an explicit patch containing effect, parameters, seed and edited stages.

The editor uses a textarea with a synchronized syntax-highlight overlay. Restoring a stage recompiles its original source. CPU and real-GPU tests cover timestamp bounds/ownership, graceful absence, disposal during delayed mapping, syntax and layout rollback, successful fragment/compute changes, independent shared-device fields, stage restoration, exported patches and benchmark restoration. General device-loss/DOM hardening remains M5/M8.
