# ADR 008: Fixed-step particle storage and HDR presentation

Status: accepted for M3.

Particles use the existing immutable queued-frame contract through `particleEffect`. Simulation state belongs to the effect program. Storage record layouts come from `particleLayout`, which applies WGSL storage alignment (including a scalar after a vec3's twelve occupied bytes). The shared baseline record has two vec4f fields: position and velocity/auxiliary state, 32 bytes per particle. The helper validates binding limits before allocating and cleans partial allocations. Ping-pong buffers ensure each invocation reads a completed previous simulation state. Single-buffer emitters update disjoint records and use separate ordered dispatches for compaction and births.

`createParticleDraw` supports one vertex per point and six vertices per instanced quad, direct counts and indirect draw arguments. Frame and parameter uniforms are visible to vertex, fragment and compute stages. Shader sources remain inspectable and pass through session shader overrides before compilation. Render passes opt into the session timestamp profiler when available; absence of timestamp-query leaves rendering unchanged.

Particle effects accumulate additive colour into rgba16float histories rather than directly into the canvas. A separate compute pass applies trail retention, then a draw adds current particles and a fullscreen pass applies exposure and Reinhard tone mapping. This keeps HDR experiments independent of optional extended-range canvas support. Point primitives remain one physical pixel, while quad diameter is specified in display pixels. The retained HDR channel is capped at 50,000 and total per-channel draw energy is bounded to 10,000 by count-aware emission scaling. Their sum is below the largest finite half-float (65,504), including the worst case of every particle hitting one pixel. Alpha is overwritten rather than added because it has no role in the opaque tone-map resolve and must remain finite under the same overlap. Trails are presentation history, retaining energy once per newly displayed simulation index, while particle motion follows every fixed simulation step. Batched updates display only their final pose, so pixel replay specifies the sequence of displayed indices as well as seed and tick count. Replay comparisons reset both particle state and history before applying the same update/render sequence. Accumulation advances only when the fixed simulation frame index changes or history is explicitly cleared/reset/resized. Repeated unchanged presentation at the same index only tone-maps the existing HDR history, making paused and reduced-motion renders identical even when the last delta remains nonzero. A signature of draw mode and parameters referenced by the compiled point/quad shaders clears and redraws the current pose when its colour or geometry changes. Shader edits participate through their compiled sources. Exposure and background changes only resolve existing HDR; trail retention changes take effect at the next displayed index.

Emitters build stable ascending free-slot and living-index lists with exclusive-scan stream compaction. Stable order avoids atomic push ordering becoming seeded randomness. GPU counts populate indirect draw arguments without synchronous CPU readback. Birth quotas use differences of cumulative rate totals, preserving fractional births over fixed steps.

Morph accepts local `setInput('text', string)` and `setInput('image', CanvasImageSource)` target replacements. Raster-mask sampling creates a CPU target buffer once per reset/input change; springs and pointer scatter remain GPU simulation. General reusable media bindings, lifetime ownership and input mip generation remain M4. Per-instance input state prevents one mount's custom text or image from affecting another.

Owned textures, particle buffers, target buffers and scan scratch are destroyed on disposal. Cached shader leases are released. Logical memory accounting includes persistent allocation and uniform snapshots, not driver VRAM. Baseline f32 storage is portable; optional half-storage experiments remain an explicitly separate capability study.

References: [WGSL alignment and size](https://www.w3.org/TR/WGSL/#alignment-and-size), [WebGPU indirect drawing](https://www.w3.org/TR/webgpu/#dom-gpurendercommandsmixin-drawindirect).
