# ADR 009: caller-encoded compute primitives

Status: accepted for M3.

Compute algorithms accept a `DeviceSession`, compile asynchronously once, and encode into a caller-owned command encoder. They never submit or read back data themselves. This allows a particle update to order integration, compaction, spawning, neighborhood construction, and drawing in one submission. Each dispatch is a separate compute pass, so storage hazards across dispatches are explicit WebGPU pass boundaries.

`createPrefixSum(session, capacity)` owns a recursive hierarchy of 256-element blocks. `encode(encoder, input, count)` returns an exclusive unsigned prefix buffer, with arithmetic modulo 2^32. `compact(encoder, flags, count)` normalizes any nonzero flag, then returns stable original row indices and a one-word GPU count. Zero-length scans and compactions are valid. Input buffers must have STORAGE usage, adequate capacity, and must not alias writable outputs.

`createSort(session, capacity, algorithm)` sorts full-width unsigned keys while retaining arbitrary unsigned associated values. Both algorithms are stable with respect to original row order for equal keys. The radix implementation uses eight four-bit passes: workgroup-local stable binary partitions, digit-major per-block histograms, hierarchical histogram scan, and global scatter. The bitonic implementation pads to a power of two and compares original row indices as ties; real maximum-u32 keys therefore precede padding. Radix needs no padded global input. Returned buffers remain valid until the next encode or disposal. They are owned by the primitive.

`createSpatialHash(session, capacity, { dimensions, maxDimensions, axes })` consumes normalized `array<vec4f>` positions. `axes: 'xy'` ignores the z/w channels, permitting packed position/velocity particles. `axes: 'xyz'` includes z. Assignment clamps each position coordinate to the grid domain, writes key/index pairs, and atomically counts cells. Radix sorting groups stable row IDs. A prefix sum of cell counts produces `cellOffsets[cell]..cellOffsets[cell + 1]`; the final offset always equals the input count. Grid keys use x + dimX × (y + dimY × z). Periodic coordinate wrapping belongs to the caller. `resize(dimensions)` changes arguments synchronously within the preallocated `maxDimensions` cell capacity, allowing parameter changes without asynchronous pipeline compilation.

`createMipGenerator(session, format)` consumes a caller-owned two-dimensional texture with TEXTURE_BINDING and STORAGE_BINDING usage. It writes each successive mip independently for every array layer, including the six square faces of a cube-compatible texture. Area-weighted box integration uses exact integer overlap numerators before float accumulation and includes odd trailing rows and columns; a 7×5 source is not silently cropped to 6×4. Supported linear storage formats are rgba8unorm, rgba16float, rgba32float, r32float, and rg32float. sRGB interpretation, normal-map renormalization, and cross-face cube seam filtering are separate material policies.

Scratch buffers are private to an instance. Reusing one instance overwrites its previous results in encoder order; callers retaining multiple simultaneous compacted streams use multiple instances. Parameter buffers are cached by immutable argument tuples, so multiple differently sized operations in one encoder cannot observe a later queue write. Sources, shader diagnostics, and logical allocation bytes are inspectable. Pipeline and shader leases go through the existing device-scoped cache; dispose releases every lease and destroys every owned buffer. Texture allocation and lifetime remain the mip caller's responsibility.

Correctness tests compare every returned element with CPU references for empty arrays, workgroup boundaries, non-power-of-two lengths, u32 overflow, nonbinary flags, stable duplicate/maximum keys, million-element scan and radix sort, dynamic two/three-dimensional grid ranges, and odd-sized 2D and six-face cube mip chains. Catalogue demos provide seeded visual inspection and presets independently of these numerical tests. Timestamp instrumentation comes from `createComputePass`, rather than custom algorithm-specific submission code.
