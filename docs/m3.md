## Issues found during validation

The first HDR renderer accumulated a stationary pose on every presentation, making paused and reduced-motion images brighten. Presentation now adds particles only for a new fixed simulation index or an explicit history clear; unchanged repeated presentations only tone-map the existing history. Changes to parameters referenced by the compiled draw shaders clear and redraw the current pose, so paused tint/size/rotation changes appear immediately. Exposure and background only resolve existing history. Counts normalize emitted energy and retained history is capped below the largest finite half-float, including the worst case of every particle overlapping one pixel. Trails remain presentation history: replay comparisons reset history and use the same render sequence.

WebKit exposed a six-ULP error when fractional coordinates determined a 7×7 cube mip footprint at values near 50. Exact integer overlap numerators removed geometric rounding before floating-point accumulation. Both hardware engines pass the original absolute tolerance. Cube faces are filtered independently; seam-aware directional filtering is a later material policy.

Invalid WGSL originally risked escaping the module compilation error scope and invalidating the active field. Modules now compile inside the shared serialized validation scope, preserve compilation diagnostics and retain the prior running instance. Successful edits reset state rather than attempting to migrate arbitrary layouts, while replaying retained custom text/image targets. Image inputs retain an owned raster snapshot after the uploader closes its decoded bitmap.

The benchmark review caught static reduced-motion runs and incomplete cancellation checks. Measurement temporarily enables motion, restores the original override and playback intent, bounds warm-up/sample counts, and checks the scenario before and after each measured submission. Mid-run transport, quality, source, parameter, input or pointer changes cancel without appending a mixed row. Regression tests exercise these changes and input replay alongside normal exports.

## Measurements and exit criteria

The fixed-scenario runner is shared by the UI and `scripts/benchmark-m3.mjs`. Default measurements cover all ten effects; the million-particle scenario fixes `flow-particles` to exactly 1,000,000 actual 32-byte records on each state side, with both point and instanced-quad paths. All runs use seed 7, DPR 1, a 512² physical display and fixed quality/time scale, thirty warm-up updates and 120 measured updates. Gate evidence must include actual buffer count/stride/bytes, 150 completed fixed ticks, selected rendering path and no GPU errors. M3 specifies particle count rather than a refresh-rate threshold; observed cadence and timestamps are reported separately.

All seventy-two measured rows completed: thirty default rows per engine (three for each effect) plus six million-particle rows per engine (three per draw path). All twelve exit runs pass, with an actual 32,000,000-byte, 1,000,000-record storage tap, at least 64,000,000 logical state-buffer bytes, 150 completed fixed ticks and 120 timestamp captures including the selected draw pass. Each gate run reports 64,000,384 logical buffer bytes including immutable uniforms; no GPU errors occurred.

Raw default records: [Chrome](benchmarks/m3-chrome.json), [WebKit](benchmarks/m3-webkit.json). Raw million-particle records: [Chrome](benchmarks/m3-gate-chrome.json), [WebKit](benchmarks/m3-gate-webkit.json). Each effect's generated note includes its parameter and measurement tables.

Timestamp results sum measured pass intervals and can be implementation-defined/quantized. Some adjacent render-pass intervals are nearly identical, and sums exceed queue-completion wall latency in these captures; the cause is unestablished. Summed GPU intervals remain diagnostics rather than whole-frame execution time, and raw results are preserved. CPU encoding, queue-completion wall latency and serialized rAF cadence remain distinct. Warm-up/compilation are excluded. Device state and load are uncontrolled; logical allocations are not VRAM.

## Scope and limits

N-body's aggregate mode approximates distant cells and does not promise exact momentum or energy conservation. Boids retains exact local neighbors within its configured radius; computational cost depends on occupancy. Attractor maps and chaotic ODEs are bounded research examples rather than cross-adapter trajectory identity guarantees. Semi-transparent particle sprites contribute linear HDR energy but the tone-mapped stage is opaque.

Morph's local raster input controls are usable now; the general media input/binding/chain layer remains M4. Timestamp support is optional, and unsupported adapters retain CPU diagnostics. Native Safari/Firefox catalogue passes, additional device classes, long-running leak/compatibility studies and optional half-storage experiments remain M8; DOM/device-loss integration remains M5. No later milestone is claimed by these checks.
