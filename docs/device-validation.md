# Physical browser validation

Open `/device-check.html` on the browser being tested. Enter the device model, operating system and browser version, exercise the native button and slider, then choose **Run checks**. Download the JSON report. It stays local to the browser until downloaded; the page sends no report to a service.

The harness covers `aurora-veil`, `grain-overlay`, `dot-matrix-field`, `grid-horizon`, `light-sweep`, `text-shimmer`, `wave-divider`, `depth-parallax`, `card-spotlight` and `border-trace`. It records initial attachment GPU completion timing, adapter information when available, DPR, actual framebuffer dimensions, unchanged reduced-motion frames, deterministic settled readback, GPU errors and teardown. The responsive fixture settles before its first pixel comparison, so column-width changes are not mistaken for motion. The border fixture enables intensity 0.2 (its preset starts at zero); spotlight uses ambient 0.02 so an offscreen pointer still produces a testable overlay. A fully settled light sweep intentionally has transparent output. Native fallback runs record the CSS/poster path separately.

Then open `/launch.html`, check the real headline and card edges, scroll through the product and divider, scrub the image with touch/keyboard, switch all three palettes and toggle reduced motion. Repeat `/launch.html?fallback=1` and inspect native text, links and the authored product image. Capture screenshots at the hero, cards and product/footer. These human appearance/control checks are separate from the harness's automated GPU assertions.

Playwright WebKit is a separate engine test, not evidence of native Safari or iPhone coverage. The benchmark reports likewise identify their actual adapter and environment. First-frame queue completion bounds readiness; it is not a browser compositor timestamp. Phone and Intel timing gates remain open until their reports exist.

For a phone on the same network, serve a production build on the Mac's LAN address and port, or use the existing published host after publishing the verified build. WebGPU requires a secure context: `http://<LAN-IP>` does not enable it on a phone. Use a trusted HTTPS host or an existing secure remote connection for GPU checks. The HTTP LAN page can still exercise native fallback behavior.

## Native Safari evidence on this Mac

The [passing Safari report](benchmarks/native-safari-p0.json) records ten ready effects, frozen poses, zero unchanged scheduled frames, no GPU errors and complete cleanup on native Safari 27.0 / macOS 26.6.2 / Apple M1 Max, DPR 2. The final production preview run also checks each shadow root before clearing fixture hosts. Its attachment-to-GPU-completion timings are retained in the passing report. The [earlier repeated-page run](benchmarks/native-safari-p0-before-shadow-check.json) observed 8–31 ms. The [initial run](benchmarks/native-safari-p0-initial.json) observed 41–996 ms; its output-presence assertion incorrectly treated the preset's inactive border and out-of-range spotlight as failures. The fixtures now explicitly enable those overlays, while the light sweep's settled transparent output remains expected. All original measurements are retained. These page runs are diagnostics at responsive fixture sizes, rather than a calibrated latency benchmark.

Native Safari inspection through the app UI confirmed the readable hero, authored console image, three-column cards, reduced-motion toggle and Paper tokens. Dragging the product slider changed its native value and visible output from 50% to 86%; switching to the forced fallback page preserved content and controls. The downloadable report's native slider field remains 50 because setting the accessibility value did not dispatch a browser input event; the later real drag is recorded here separately.

## Physical iPhone evidence

The paired iPhone ran the HTTPS Cloudflare preview in native Safari. The ten-fixture harness displayed **Checks passed**; its native button incremented to 1 and a real slider drag changed 50 to 83. The Ember hero, real headline, authored product image, divider and horizon were inspected. Following the native product link worked, and dragging its scrubber changed 50% to 84% and changed the rendered image. The [observation record](benchmarks/iphone-safari-p0-observation.json) explicitly separates UI observations from raw measurements. Safari accepted the JSON download on the phone; no copy of that raw report was retrieved onto this Mac.

The phone revealed Safari's floating toolbar covering the footer controls. Mobile bottom padding now leaves room for the toolbar and home indicator, and updated DPR 1/2 captures pass. Mirroring subsequently lost the device, so the physical footer-fix recheck, palette, motion-toggle, fallback and card appearance checks remain open. The original phone/Mac report's cleanup query checked light DOM only; the final harness checks each shadow root before clearing empty fixture hosts. The corrected cleanup check passes native Chrome and native Safari 27 on this Mac. The earlier reports are retained as their original evidence. This phone pass does not establish sustained performance or exact Safari 26 coverage.
